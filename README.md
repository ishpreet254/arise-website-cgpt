# ARISE Website

"Rise Beyond Imagination" — built section by section per the Master Spec's build order
(Section 9). Global nav and the Hero section are done; everything from Services onward
is still an empty placeholder `<section>`.

## Stack

- **Next.js 16** (App Router), plain JavaScript — no TypeScript, to keep the learning
  curve low.
- **No Tailwind** — styling is plain CSS using custom properties (design tokens), per
  Master Spec Section 3.2.
- **GSAP** installed, not yet wired up — will drive all scroll/animation work per
  Master Spec Section 7.
- No backend yet (Supabase is Phase 2, deferred until the frontend is live).

## Design tokens (done)

`src/styles/tokens.css` holds every color, type, spacing, radius, and motion value from
Master Spec Section 2 — dark theme as `:root` (default), light theme as a
`[data-theme="light"]` override block. The color values are the spec's proposed
starting palette; swap them for exact brand hex codes if/when those exist (Master Spec
Section 8, item 3).

**Fonts:** Fraunces (display, Google Fonts) and General Sans (body, Fontshare) are
loaded via plain `<link>` tags in `src/app/layout.js` — not via `next/font`, so there's
no build-time dependency on reaching those CDNs. They load like any normal web font,
the moment a browser opens the page. **Double-check General Sans' current commercial
license on Fontshare before this goes live** (Master Spec Section 8, item 4).

**Theme toggle:** lives inside the hamburger panel in `Nav.js` (Master Spec 4.1–4.2).
Flips `data-theme` between `dark`/`light`; choice persists across visits via
localStorage under the `arise-theme` key. The standalone dev-only `ThemeToggle.js` has
been removed now that the real toggle is in place.

## Structure

```
src/
  app/
    layout.js        — root layout, page metadata, global CustomCursor mount
    page.js           — composes the sections below, in sitemap order
    globals.css        — design tokens import + all built-section styles
  components/
    global/            — site-wide chrome, used on every load
      Nav.js            — built: logo, top links, hamburger panel, theme toggle
      Footer.js         — stub
      CustomCursor.js   — built: premium desktop cursor enhancement
    sections/           — one file per Master Spec section 5.x, in sitemap order
      Hero.js           — built
      Services.js       — stub
      About.js          — stub
      Portfolio.js      — stub
      Testimonials.js   — stub
      FAQ.js            — stub
      ReachOut.js       — stub
      Contact.js        — stub
  lib/                 — empty; for shared utilities (theme context, GSAP helpers) later
  styles/
    tokens.css          — design tokens (Master Spec Section 2)
public/
  hero/                 — hero background video/poster, per theme
  logo/                 — ARISE logo mark
```

Sections marked "stub" render an empty `<section>` with no styling — placeholders
marking where that spec section will be built, nothing more.

## What's deliberately NOT here yet

- Any visuals, layout, or animation in sections after Hero — still empty
- Contact/enquiry form wiring (Formspree/EmailJS)
- Any generated assets (video, images) beyond what Hero and Nav already use — those are
  generated by you, not this tool

## Running it locally

```
npm install
npm run dev
```

Then open http://localhost:3000 — you'll see the nav and Hero section rendered; every
section below Hero is still an empty placeholder, which is expected at this stage.
